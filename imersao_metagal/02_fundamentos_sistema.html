BANCO DE DADOS // O QUE É

O que é um banco de dados?

É um sistema feito para guardar informação de forma estruturada — em tabelas, com regras, relacionamentos e consulta rápida. Não é um arquivo solto na pasta.

Arquivo soltoPlanilha no e-mail, CSV no Downloads. Fácil de perder, difícil de compartilhar com segurança.
BancoTabelas (fornecedores, pedidos, itens). A aplicação lê e grava de forma confiável.

BANCO DE DADOS // PRA QUE · COMO

Pra que serve e como funciona

Pra que servePersistir dados do negócio: pedidos, usuários, status, histórico. A solução “lembra” depois que você fecha a tela.
Como funcionaVocê cria tabelas e colunas. A aplicação pergunta (consulta) ou grava (insert/update). O banco responde com linhas.

INTELIGÊNCIA ARTIFICIAL // O QUE É

O que é a IA?

No nosso contexto, é um sistema treinado em enormes volumes de texto e código, capaz de entender linguagem natural e gerar respostas úteis: texto, análise, código, estrutura.

  • Não “pensa” como humano — prediz a melhor continuação com base no que aprendeu.
  • Funciona melhor com contexto claro: o que você quer, com quais dados, em qual formato.
  • É um parceiro de execução, não um oráculo infalível — você valida o resultado.

GIT // O QUE É

O que é o Git?

É um sistema de controle de versão que roda na sua máquina. Registra o histórico do projeto: o que mudou, quando e por quê — sem “arquivo_v2_final_FINAL.xlsx”.

  • Cada “foto” do projeto se chama commit.
  • Você pode voltar no tempo se algo quebrar.
  • Várias pessoas podem trabalhar no mesmo projeto sem sobrescrever o trabalho uma da outra.

COMPARATIVO // GIT × GITHUB

Diferença entre Git e GitHub

Git• Ferramenta local (no seu computador)
• Controla versões dos arquivos
• Funciona offline
• É o “motor” do histórico
GitHub• Plataforma online (nuvem)
• Hospeda repositórios Git
• Colaboração, backup remoto, PRs
• É o “cofre + rede social do código”

Analogia: Git é o caderno de rascunhos com páginas numeradas. GitHub é a nuvem onde esse caderno fica guardado e compartilhado.

GIT = FERRAMENTAGITHUB = PLATAFORMA

COMPARATIVO // FRONT × BACK

Frontend vs Backend

Frontend• O que o usuário vê e clica
• Telas, botões, gráficos, formulários
• Roda no navegador
• Base: HTML, CSS, JavaScript
Backend• O que acontece por trás
• Regras, autenticação, APIs, banco
• Roda no servidor
• Recebe pedidos do front e responde

Exemplo: você clica em “Salvar pedido” (front) → o servidor valida e grava no banco (back) → a tela confirma.

ARQUITETURA // PEÇAS AO REDOR

Onde entram Git, GitHub e IA

Git + GitHubGuardam e versionam o código do front e do back. Histórico + backup + colaboração.
IAAcelera a construção dessas peças: gera tela, lógica, consultas, documentação.
IDE (VS Code)A oficina onde você edita o sistema e conversa com a IA no mesmo lugar.
  • Sistema em produção: usuário → front → back → banco.
  • Sistema em construção: você + IA na IDE → commits no Git → remoto no GitHub.
