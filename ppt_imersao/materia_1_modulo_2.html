INÍCIO // CURSOR

Primeiro projeto no Cursor

Abra uma pasta de trabalho, conheça o layout (explorer, chat, terminal) e entenda que tudo gira em torno dos arquivos do projeto na sua máquina.

  • Crie ou abra uma pasta vazia dedicada ao curso.
  • Use o chat da IA com o contexto do workspace ligado.
  • Salve arquivos com extensão correta (.html, .css…).
IA BUILDER02
PROMPTS // IDIOMA

Prompts: o idioma para conversar com a IA

Escreva em português claro se for seu idioma de trabalho: a IA entende e gera código. O que importa é ser específico sobre objetivo, público e restrições.

  • Contexto: quem vai usar e em qual dispositivo.
  • Entregável: “uma página HTML única”, “sem framework”, etc.
  • Tom visual: cores, estilo (minimalista, corporativo…).

PROJETO // CURRÍCULO

Primeiro projeto: currículo

Um site currículo em HTML/CSS é o projeto ideal: é visual, cabe em poucos arquivos e você publica depois no GitHub Pages.

EstruturaSeções: cabeçalho, experiência, formação, habilidades, contato.
VisualTipografia legível, contraste e layout responsivo simples.
IA BUILDER04
REFINO // CURRÍCULO

Técnicas para ajustar o currículo

Peça ajustes em iterações pequenas: uma seção por vez, ou “deixe o hero mais compacto”. Compare versões e mantenha o que funcionar.

  • Copie/cole seu texto real e peça reformatação, não inventar carreira.
  • Pedidos do tipo: “reduzir texto em 30%”, “alinhar à vaga X”.
  • Peça checklist de acessibilidade (contraste, headings).
IA BUILDER05
PROMPTS // ASSERTIVIDADE

Técnicas para ser mais assertivo no prompt

Prompt bom = resultado mensurável. Use formato, exemplos e limites. Se a IA errar, mande o erro exato ou um print do comportamento.

  • Role + tarefa: “Atue como front-end e crie…”
  • Restrições: “sem bibliotecas externas”, “apenas uma página”.
  • Critério de pronto: “deve funcionar ao abrir o HTML no navegador”.

EXECUÇÃO // NAVEGADOR

Rodando o projeto

HTML estático pode abrir direto no navegador; para evitar limitações de alguns recursos, use um servidor local (plugin Live Server ou comando simples).

  • Arquivo principal: normalmente index.html.
  • Atualize a página após salvar; plugins podem recarregar automaticamente.
  • Console do navegador (F12) mostra erros de JS ou caminhos quebrados.

FLUXO // LOCAL → NUVEM

Da máquina local para a nuvem

No seu computador o projeto é só arquivos em pasta. Na nuvem (GitHub) ele vira repositório: backup, histórico e base para publicar o site.

LocalEdição rápida, testes no navegador, sem depender de internet.
NuvemCompartilhamento, CI/CD leve, GitHub Pages para o currículo online.
IA BUILDER09
VERSÕES // MOTIVAÇÃO

Por que criar versões do seu projeto?

Sem versionamento, você só tem a pasta “de agora”. Com commits, cada mudança fica registrada: volta atrás, compara, colabora sem medo.

  • Segurança: desfazer uma alteração que quebrou o layout.
  • Histórico: ver o que mudou e por quê.
  • Publicação: GitHub usa o estado do repo para servir o site.
IA BUILDER10
FUNDAMENTO // GIT & GITHUB

Git e GitHub: o que é, para que serve e como funciona?

Git é o sistema de controle de versão na sua máquina. GitHub é o serviço online que hospeda cópias do repositório e ferramentas em volta (issues, Pages, Actions).

  • Fluxo mental: editar → commitar → enviar (push) para a nuvem.
  • O histórico é um grafo de commits, não um único arquivo “final”.
IA BUILDER11
COMPARATIVO // GIT × GITHUB

Git × GitHub

Git (local)Ferramenta de linha de comando ou integrada na IDE. Roda no seu disco. Funciona até offline (commits locais).
GitHub (remoto)Hospedagem + colaboração. “Origin” é o servidor onde você envia e puxa alterações.

Analogia: Git é o motor; GitHub é a garagem na internet onde o carro também fica guardado.

GITHUB // CONTA

Criando uma conta no GitHub

Cadastro gratuito, username público (URL do seu perfil) e e-mail para recuperação. Ative 2FA quando possível para segurança.

  • Escolha um username profissional — aparece em links de portfólio.
  • Confirme o e-mail antes de criar o primeiro repositório.

GITHUB // INTERFACE

Por dentro do GitHub

Navegue por repositório, lista de arquivos, commits, branches e configurações. O botão verde Code mostra a URL para clonar.

  • README.md aparece na página inicial do repo.
  • Settings: visibilidade, GitHub Pages, colaboradores.

SETUP // GIT

Baixando e instalando o Git

No macOS use o instalador oficial ou Xcode Command Line Tools. Depois confira no terminal: git --version.

git --version

Instale também as ferramentas de merge se o instalador oferecer; ajudam em conflitos futuros.

CONFIG // GIT

Configurando o Git no Cursor

Defina user.name e user.email iguais aos do GitHub (e-mail principal ou o privado do GitHub). Isso assina seus commits.

git config --global user.name "Seu Nome" git config --global user.email "seu@email.com"

CURSOR // INTEGRAÇÃO

Integrando o Git no Cursor

A aba Source Control mostra arquivos modificados. Você pode inicializar o repositório, fazer stage, commit e sincronizar com o remoto sem sair do editor.

  • Initialize Repository na pasta do projeto (primeira vez).
  • Autenticação GitHub: token (PAT) ou GitHub CLI — conforme o fluxo que adotarmos na aula.
IA BUILDER17
GIT // CONCEITOS

Conceitos principais: Commit, Push e Pull

CommitFoto do estado atual dos arquivos, com mensagem. Fica no histórico local (e depois no remoto).
PushEnvia seus commits locais para o GitHub (atualiza o remoto).
PullTraz alterações do remoto para sua máquina (útil em time ou outro computador).
IA BUILDER18
PRÁTICA // COMMIT

Fazendo o primeiro commit

Adicione arquivos ao stage, escreva uma mensagem clara (ex.: “Currículo: estrutura inicial”) e confirme. Esse é o marco zero do histórico.

git add . git commit -m "feat: currículo HTML inicial"

Boas mensagens: imperativo, curtas, descrevendo o que mudou — não “ajustes” vago.

EVOLUÇÃO // AJUSTES

Ajustes do projeto

Iteração contínua: corrija textos, melhore responsividade, otimize imagens. Cada rodada pode ser um novo commit — pequeno e frequente vence mudança gigante de uma vez.

  • Teste no celular e no desktop antes de dar push.
  • Commits atômicos: uma ideia por commit quando possível.
IA BUILDER21
HISTÓRICO // GIT

Voltando no tempo com o Git

O histórico permite inspecionar commits antigos, comparar versões e, com cuidado, reverter alterações. Na IDE você vê a timeline; na linha de comando, git log e comandos de checkout/revert.

  • Preferir revert em trabalho compartilhado (não reescreve histórico público).
  • Branches ajudam a experimentar sem medo antes de fundir na principal.
IA BUILDER22
NUVEM // GITHUB

Subindo o projeto para a nuvem (GitHub)

Crie o repositório vazio no GitHub, adicione o remote, faça push da branch principal. O código local e o remoto ficam sincronizados.

git remote add origin https://github.com/usuario/repo.git git push -u origin main

Se a branch padrão for master, adapte o nome; o GitHub hoje costuma usar main.
